# 原始资料契约

所有资料均为本地合成。JSONL一行一条来源观察，row_id仅标识该观察；同业务ID可以在不同revision、批次或接收位置出现。未写revision的静态目录按文件给定值解释，不隐含线上查询。事实字段中的None为缺少来源值，不是零或否。

金额字段以minor结尾时为该币种最小单位整数；数量、位置、时间的单位以字段后缀和政策说明为准。日期为ISO日期；绝对时刻携带偏移；原始received字段决定可见性，不能仅按发生日期提前使用资料。后续业务修改以相同格式输入，不限定样本编号。

## 业务政策

### matching

净结算=本行gross-fee-明确引用退款。M1到账窗口为结算日后1到4工作日，周六日不算；样本结算日统一2026-11-20。不同渠道可共用同商户回款；无商户/币种/工作日依据不能拼款。

### amount

全部币种最小单位整数；允许拆分核销且每个源行/银行行的累计核销不超有效金额。无明确外汇兑换记录不跨币种凑平。所有可行候选/多解必须显式展示，排序不是唯一性证据。

### confirmations

人工接受指定组合及核销金额，接受时核验源行revision/残额/兑换事实；拒绝保留理由，撤销恢复残额但不覆盖历史报告。人工确认可以按业务提供额外引用，不能任取算法分数自动认领歧义款。

### close

要求popup/direct/partner销售和结算覆盖齐全且所有已声明本期应收均确认核销、差额有批准的明确调整依据才可关账；覆盖missing不等于零。旧期更正进入下一开放期间并关联旧行，旧报告不变。

## 资料检查

`python -m unittest discover -s tests -v`只检查资料字节与格式，不是尚未开发业务功能的验收。manifest.json中的摘要对应提交内原始字节，收到后续批次应独立登记来历，不修改旧原始记录。
